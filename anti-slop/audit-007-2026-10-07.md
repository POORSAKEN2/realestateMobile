# My Tickets crash and list-state audit

Mode: after (session override). Scope: the approved mobile tab-crash and list-error plan. This report covers changed UI and behavior, not full Support Center acceptance.

## Findings and resolutions

1. HIGH, R-26 / R-27: switching to My Tickets triggered a late NativeWind CSS-variable upgrade; its warning serializer invoked React Navigation getters and crashed. Both tab buttons now initialize shadow variables with unconditional `shadow-none`, retaining selected `bg-panel shadow-sm`. FAQ and ticket wrappers have distinct keys. The CSS compiler regression confirms variable capability exists before selection. Expo Router navigation and installed dependencies are preserved.
2. HIGH, R-27: failed initial reads appeared as empty collections with zero counts. Loading, initial failure, successful empty, populated, and failed cached refresh states are now separate. Retry uses the shared Button and real query refetch. Cached records remain visible with a stale-data warning; cached empty failures do not display a fresh empty-result message.
3. MEDIUM, R-31: empty-state instructions referenced a nonexistent Ticket button, and FAQ collection emptiness was confused with an unsuccessful search. Copy now references the existing + button and distinguishes those cases. Counts appear only when query data exists.
4. HIGH, R-25: selected tabs and the reused secondary Button used the accent token on a light panel. Their labels use `primaryContent`: 8.63:1 on the light panel and 7.11:1 on the dark panel. Tabs also have a 44-point minimum height and wrapping space rather than a fixed 40-point height.
