# Automatic billing confirmation audit

Mode: after (session override). Scope: the requested replacement of manual billing synchronization with automatic access updates.

## Findings and resolutions

1. HIGH, R-27: delayed server confirmation left the billing screen dependent on a later refresh or SDK event. Added foreground entitlement polling and periodic fresh store checks, with automatic reconciliation retries for mismatched access. Server confirmation still controls access.
2. MEDIUM, R-31: the warning could show Professional beside Professional Monthly without explaining trial or read-only access. Server labels now identify those states. Purchase warnings explain automatic confirmation; store errors show Store check delayed.

## Design read

Preserve Terrane's existing billing cards, Raleway typography, purple actions, spacing, wrapping text, and theme tokens. ENERGY 2 / RHYTHM 2 / MOTION 1. The change adds no assets, visual treatments, controls, navigation, or animations. Status text describes the automatic behavior and the source of access.

## Delivery checks

- Hard Gate PASS within changed copy and behavior: no fabricated access claims or new controls; loading/error handling retained. On iPhone 17 Pro / iOS 26.2, opening Plan & Billing showed Professional server access and Professional Monthly store purchase with no mismatch warning. Trial/read-only distinction has regression coverage. Broader purchase lifecycle acceptance is unverified.
- Purpose-Gate PASS within changed scope: existing visual treatments preserved; the warning explains purchase confirmation and the server label distinguishes authorization states.
- Liveliness PASS within changed scope: existing billing hierarchy and 2/2/1 dials preserved; no new decoration or animation.
- Craftsmanship PASS: 45 focused Node tests, TypeScript checking, and diff whitespace checks passed. Provider tests cover delayed recovery, periodic checks without offering reloads, background pause/resume, manager restrictions, and disposal. Synchronizer tests retain tenant-change and concurrent-event protection.

## Operational limits

This is near-realtime polling, not WebSocket push. Foreground server reads run every 5 seconds while confirmation is pending or access is unknown, otherwise every 30 seconds; failed reads use 30 seconds. Store checks run every minute. Polling pauses in the background and app return validates again. In-flight work may finish after backgrounding. Backend webhook delivery and reconciliation credentials must work for purchased server access to become confirmed.

Live delayed-webhook timing, renewal, refund, Android, web, and enlarged-text runtime behavior were not verified. No purchase, restore, deployment, commit, or push was performed.
